# 《竹林守卫：熊猫乱斗》视觉设计系统

> 版本：v1.5
> 状态：M0 起强制执行  
> 更新日期：2026-09-02

## 1. 核心方向

视觉采用“东方绘本 + 卡通武侠”：圆润、温暖、轻松，使用宣纸纤维、墨线、竹木与少量剪纸色块。画面是原创熊猫武者世界，不模仿任何现有影视或游戏 IP 的角色造型。

固定关键词：`俯视 3/4`、`圆润轮廓`、`手绘墨线`、`宣纸颗粒`、`竹林`、`暖色武侠`、`清晰剪影`、`低细节战场`。

禁止：写实毛发、3D 塑料感、像素风、霓虹科幻、现代 SaaS 面板、图片内文字、水印、复杂背景、不同元素族混用不同视角。

## 2. 色彩、线条与光源

| 角色 | 色值 | 使用 |
|---|---|---|
| 墨黑 | `#202622` | 统一外轮廓、熊猫深色部分、正文 |
| 宣纸 | `#F3E6C8` | 熊猫浅色、卡片底、亮部 |
| 竹绿 | `#4F8F55` | 地面、竹系元素 |
| 嫩竹 | `#9BCB66` | 玩家弹道、成长、正向反馈 |
| 铜金 | `#E3A83B` | 武器、关键边框、货币 |
| 妖紫 | `#7651A8` | 腐化与冲锋敌人 |
| 危险红 | `#D9554D` | 追击敌人、伤害与预警 |
| 气功青 | `#53B8B2` | 远程敌人、护盾与能量 |

- 角色与图标使用约占成品宽度 2.5%–3.5% 的深墨外轮廓，内部线条约为外轮廓一半。
- 光源统一来自左上 10 点钟方向；右下允许柔和暖灰阴影。
- 单个元素使用 4–7 个主色块，避免碎细节和高频纹理。

## 3. 元素族规格

### 3.1 可玩角色

- 生成源：1024×1024 PNG，真实透明背景，单角色，无文字、地台和场景。
- 标准成品：256×256 PNG；内容占宽度 62%–78%、高度 70%–88%。
- 锚点：底部中心；脚底距画布底边 0%–6%。
- 视角：俯视 3/4，身体朝屏幕下方，脸部仍清楚。
- 运行时：M0 基础熊猫显示宽高 68×68 CSS/game pixels。
- 一致特征：圆耳、黑白脸、1:1.7 头身、短粗四肢、暖棕武侠背心、竹绿腰带。

### 3.2 普通敌人

- 生成源与标准成品同角色族：1024×1024 → 256×256 PNG，底部中心锚点。
- 运行时：普通 54×54；冲锋 62×62；远程 58×58。
- 共性：同一绘本墨线与宣纸颗粒；腐化动物而非恐怖怪物；脸部和攻击方向清楚。
- 追击族：危险红，圆/三角轻量轮廓，向前扑咬。
- 冲锋族：妖紫，前重后轻、角或肩甲明确，蓄力方向清楚。
- 远程族：气功青，高挑轮廓，发光器官与弹道同色。

### 3.3 最终 Boss

- 腐竹巨灵生成源：1024×1024 PNG，真实透明背景，单体，无文字、地台、场景和额外小怪。
- 标准成品：512×512 PNG；主体占宽度 72%–88%、高度 78%–94%，底部中心锚点，根部距底边 0%–4%。
- 运行时：约 176×176 game pixels；厚重根系、宽肩和发光腐化核心必须在该尺寸下一眼可辨。
- 造型：由扭曲腐竹与盘结根须组成的巨型守卫，俯视 3/4；外轮廓使用深墨，主色为枯竹褐、墨黑与妖紫，危险裂隙使用危险红，左上受光。
- 阶段变化由代码叠加妖紫脉冲、腐化边界与预警，不另行混用不同视角的单张图片；受击只允许短促闪白和轻微压缩，不允许击退。
- 招式预警由统一透明特效纹理配合代码控制范围：根刺为腐化土痕、盘结根须和不闭合危险红裂边；冲击波为厚薄不均的妖紫墨浪与少量宣纸高光；召唤为妖紫巢痕。禁止使用完整红圆、黑色叉线或调试感网格；预警范围必须与实际命中范围一致。

### 3.4 武器、道具与状态图标

- 生成源：1024×1024 PNG；标准成品 256×256 PNG；运行时图标 36×36。
- 居中安全区：内容不得超出中间 78%；四边至少 11% 透明边距。
- 视角：轻微 3/4，左上受光；墨线与角色族一致。
- 同类图标使用统一米白宣纸圆牌底与墨色外圈；稀有度后续通过外框和角标叠加，不重新绘制主体。
- 投射物可复用武器主体的简化剪影，但运行时必须保持 12–20 像素仍可辨认。

### 3.5 战场地面

- 生成源：1024×1024 正方形低对比无缝纹理。
- 主体为竹林土径、苔藓、淡墨叶影和宣纸颗粒；不出现角色、文字、强焦点或高亮物体。
- 明度对比低于角色和弹道；危险红、妖紫、气功青不得大面积用于地面。
- 运行时平铺，不拉伸；地图边界仍由代码绘制清晰轮廓。

### 3.6 HUD 与菜单材质

- 信息文字始终使用 DOM，不烘焙到图片。
- 生成纹理为无文字的宣纸、竹木包边、墨迹与铜扣；允许平铺或作为装饰层，不能承担数值表达。
- 持久 HUD 只占左上生命簇、顶部中央时间簇、右上闪避簇和左下双武器簇；中心与下方移动区保持清空。
- 战斗面板透明度 88%–94%，边缘有 1–2 像素暖金/竹木线，不使用玻璃拟态或均权卡片墙。
- 桌面运行时：生命簇最大 300×96，中央簇最大 260×60，单个武器槽 170×58。

### 3.7 战斗特效

- 生成源：1024×1024 透明 PNG；标准成品：512×512；运行时按判定范围等比缩放，中心锚点。单张只包含一种效果，不含角色、文字、场景、完整圆框和水印。
- 根刺预警纹理：俯视腐化土壤、3–5 条从中心向外分叉的墨黑根须裂纹、少量危险红内透光，边缘自然消散；主体占画布 72%–84%，不得形成闭合圆环。
- 护盾气罩纹理：俯视 3/4 的墨青半球形笔触，主要能量集中在角色下半身和两侧，顶部保留透明缺口；只在获得、受击时增强，常态透明度低于 24%。
- 根刺爆发可使用代码绘制立起根须和尘土，但必须复用预警纹理的枯竹褐、墨黑和危险红；不得重新出现几何标记。
- 竹杖横扫：以攻击朝向为中心的约 90° 扇形，外沿使用 5–8 像素铜金亮弧，内部使用低透明嫩竹绿气流；显示半径必须与实际命中半径一致。
- 山岚第 4 次旋风：扩大为 180°，增加第二道错位铜金弧与短叶痕；不得画成全屏圆环。
- 铁竹盾击：使用约 70° 的短扇形，气功青半透明盾面配合粗短震线、墨青碎片和前向冲击点；轮廓必须不闭合，不能复用竹杖的长弧和嫩竹气流，也不能绘制完整青色圆环。
- 飞叶弹道：复用标准化飞叶主体，运行时主体保持约 18–22 像素可见尺寸；使用深墨外拖尾与嫩竹绿内芯，暴击改为铜金内芯，不使用敌方气功青。
- 飞叶命中：沿飞行方向释放 3 条短叶痕，普通命中控制在 26 像素内，暴击控制在 38 像素内。
- 爆竹命中：使用不闭合的暖金纸屑、朱红火瓣、墨灰烟团和少量竹屑形成不规则爆发；主体按实际爆炸半径缩放，不使用完整爆炸圆、规则放射线或几何星形。
- 旋转竹刃：竹刃沿角色近身轨道旋转，轨迹只使用 2–3 段错开的嫩竹绿风痕，不画闭合圆环；Lv.3 增加第二把对称竹刃，Lv.5 增加第三把，实际命中带与可见轨迹一致。
- 熊猫酒葫芦：落地点使用不规则琥珀酒渍、朱红火舌和少量墨灰烟边，边缘自然断开并淡出；Lv.3 同时形成两处酒焰，不使用纯色透明圆表示范围。
- 竹弩机关：机关为竹木与铜件组成的低矮弩台，朝当前目标转向；弹道使用细竹箭身、铜金箭头与短促嫩竹尾痕，Lv.3 同时部署两台，禁止使用粗光柱或敌方妖紫色。
- 普通命中停顿不超过 20ms，重型暴击停顿不超过 45ms；普通攻击不产生大幅镜头震动。
- 敌方弹幕以 8–12 像素妖紫菱形核心、危险红渐细拖尾和米白高光点表达敌意；飞行时允许小幅旋转或双侧妖气火花，碰撞半径不得依赖发光外圈。与玩家嫩竹绿/铜金叶形弹道保持形状和颜色双重差异。
- 同屏特效按“危险预警 > 敌方弹幕 > 玩家弹道 > 命中数字 > 装饰粒子”排序；高密度时先减少装饰叶片，不削弱危险信息。

### 3.8 角色与敌人动画

- 动画必须从已批准的静态成品作为种子帧整条生成，不逐帧独立生成；同一条动画共享画布、缩放和底部中心锚点。
- 玩家：Idle 6 帧、Run 8 帧、Attack 6–8 帧；运行时根据水平速度翻转，攻击动画朝最近有效目标方向播放。
- 普通敌人：Move 6–8 帧、Attack 4–6 帧；追击族突出扑咬，冲锋族突出压低重心与突进，远程族突出聚气与释放。
- 帧间角色高度漂移不得超过运行时 2 像素；脚底基线保持一致，轮廓、服装、武器和主色不得在帧间变化。
- 移动循环允许 4%–7% 的上下起伏和轻微身体倾斜；攻击动作允许短促前冲、回弹和挤压，不允许旋转整张图片代替动作帧。

### 3.9 字号与可读性

- 桌面端任何可读文字不得低于 14px；`small`、快捷键、标签、卡片说明和价格也遵守此下限。
- HUD 正文 14px，关键数值 17–20px；商城标题 30px 以上，卡片名称 19px 以上，说明与价格 14–16px。
- 字号放大后优先增加面板内边距或减少非关键文案，不压缩战场中心与下方移动区域。

- 文件名使用稳定英文 kebab-case，不添加临时序号作为运行时 ID。

- 不覆盖已批准成品；重新生成使用 `-v2`，通过对比后再由用户明确批准替换。

## 5. 生成与验收

每个元素族必须共享同一提示骨架，明确视角、媒介、色板、线宽、光源、画布、透明度、主体占比和禁止项。不同主体只替换“角色/物品特征”段。

验收必须同时查看原图和真实运行尺寸：

- 透明背景真实存在且无白边。
- 轮廓、视角、光源和颗粒语言与同族一致。
- 缩小后角色、敌人行为类型和武器仍一眼可辨。
- 底部中心锚点一致，无明显跳高或漂移。
- HUD 没有遮挡中央和下方移动区。
- 最后代码状态有浏览器截图，且截图中的资产来自项目目录。
