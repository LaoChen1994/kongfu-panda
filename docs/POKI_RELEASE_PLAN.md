# Poki 发布计划

更新：2026-09-22。本文是后续执行清单，不代表已经接入 SDK、通过审核或发布。

## 当前入口与范围

- [GitHub Pages 试玩地址](https://laochen1994.github.io/kongfu-panda/)可用于开发者申请；新功能只有合并并完成 Pages 部署后才会上线。
- 本轮：中英文共用一份构建、菜单/暂停切换、浏览器语言识别、偏好保存、玩家文案翻译。保留稳定 ID、战绩、数值与随机规则。
- 暂用英文标题 **Bamboo Guardians**（对应当前界面“竹林无双”）；正式提交前由作者确认名称并检查重名，不能宣称关联既有影视 IP。
- 非本轮：SDK、广告奖励、平台提交、账号与条款确认、正式宣传素材、新玩法。

## 按顺序执行

| 阶段 | 工作 | 交付与验收 | 依赖 |
|---|---|---|---|
| P0 双语 | 中文/英文全路径、术语统一、存储失败回退、长文案布局 | 自动测试；选人→加载→战斗→升级→商城→结算双语截图；切换不重开本局 | 本次开发 |
| P1 提交准备 | 检查原创性、图标/字体/音频来源、无文字烘焙；核查灵茶/竹露设定 | 资源来源与生成迭代记录；英文文案人工复核；申请开发者权限 | 作者申请；P0 合并 |
| P2 平台适配 | 独立 Poki 构建入口；接入 SDK 加载与游玩生命周期；保留 Pages 版本 | Inspector 检查；SDK 加载失败或被阻断时不阻止游戏；无重复生命周期事件 | 开发者后台可用；确认本阶段 |
| P3 Web 验收 | iframe、触控、横竖屏、失焦/恢复、无痕存储、冷启动与包体 | 指定尺寸截图、真机记录、网络瀑布、帧率基线；生产包无调试入口 | P2 |
| P4 平台试玩 | 上传 Web 构建，内容审核后申请试玩；按反馈修复 | 记录构建版本、内容审核结果、试玩问题清单 | 作者阅读并接受平台条款 |
| P5 上线 | 按平台反馈确认商业化方式；准备静态/动态缩略图与介绍；完成审核 | 发布检查表全部勾选；保留上一版构建和回退说明 | 平台允许进入后续测试/发布阶段 |

Poki 支持提交原型，上传并不等于公开上线；内容审核通过后再申请首次试玩。条款由作者本人确认，不由自动化代为接受。[提交指南](https://developers.poki.com/guide/adding-your-game)

## SDK 事件验收设计（待实现）

- 加载就绪不等于开始游玩；在首个有效游戏输入时进入 gameplayStart。
- 战斗→升级、商城、暂停、失焦、结算：只发送一次 gameplayStop。恢复到可操作战斗再进入 gameplayStart。
- 广告期间冻结战斗、屏蔽输入、静音；不得重复发送生命周期事件。
- 若采用 commercialBreak，只放在暂停/整备结束、即将回到战斗的节点，不放在打开菜单的瞬间。广告失败仍可继续；不自建广告频率计时器。
- 本轮不新增“看广告复活/刷道具”等玩法；奖励规则需要独立设计确认。

以上为项目事件映射；开发时再按最新 SDK 文档核对具体 API 和 Inspector 结果。[平台要求](https://developers.poki.com/guide/requirements-quality)

## 设备、性能与生产构建检查

- [ ] 16:9 iframe：640×360、836×470、1031×580；额外回归项目桌面 1280×720、手机横屏 844×390、667×375。
- [ ] 平板必须显示触控方案，不能只按宽度判断；当前宽度驱动方案需要在 P3 核查/修正。
- [ ] Android Chrome、iPhone Safari、平板真机：移动+闪避、多点触控、旋转、切后台恢复、滚动不带动父页面。
- [ ] 无痕/禁用存储、无缓存、限速、断网重试；静态资源随构建提供，不依赖外部字体/CDN。
- [ ] 告知玩家：只保存已完成战绩，退出不恢复当前对局。当前需要补充明确提示。
- [ ] 记录首屏可操作和进入战斗时间、初始下载量、峰值内存与密集战斗帧率；先测量再决定动画资源压缩/分包，不能只隐藏加载画面。
- [ ] 清除生产调试工具、测试 URL 能力和验证资源；从打包产物运行一次完整正常局与失败局。
- [ ] Pages 与 Poki 构建分别检查；Pages 不应强制依赖 Poki SDK。

设备、存储、外部资源、干净构建与缩略图要求以官方页面为准，提交前重新核对。[平台要求](https://developers.poki.com/guide/requirements-quality)

## 发布操作与回退

1. 作者确认开发者权限、名称、介绍和条款。
2. 为待提交 commit 生成可复现的生产包，记录 commit、构建命令、包体大小、验收目录。
3. 用 Inspector 检查，再上传该版本；记录平台版本编号和问题反馈。
4. 只针对反馈修复，每次重复双语及邻近玩法回归。
5. 获得平台发布许可后提交正式素材；上线后核查实际入口、存储与语言选择。
6. 保留上一个验证通过的构建；发现阻断问题时按后台能力恢复旧包或提交热修，不把 Pages 部署成功等同于 Poki 发版。

## 双语维护规则

中文源文案是 `src/translations.ts` 的键，英文是对应值；完整句子使用 `{0}` 占位，不能拼接碎片导致语序错误。内容配置保留原始稳定 ID，展示时翻译，稀有度样式和随机权重不得读取翻译后的文字。后续新增玩家文案必须同时增加英文并验证长文本布局。默认中文浏览器用简中，其他语言回退英文，手动选择优先。

集中管理文案、菜单切换和适配较长翻译符合官方本地化建议；本轮只做中英文，不扩展其他语种。[本地化指南](https://developers.poki.com/guide/localization)
